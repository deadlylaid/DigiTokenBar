# 2단계: 진화 엔진

정리일: 2026-11-08 · 상태: **확정, 구현함 (2026-11-09).** 아래 [정할 것](#정할-것) 세 가지는 제안대로 확정됐다. 구현 내용은 [구현 메모](#구현-메모)에 있다.

## 목표

- 화면 없이 Swift 코드만으로 돌고, 가짜 사용 기록을 넣어 테스트할 수 있는 진화 엔진을 만든다.
- 원본의 동반자(`CompanionStore`) 자리에 연결하되, 원본 파일은 최소한만 고친다(0단계 원칙).

## 들어오는 것과 나가는 것

| 들어오는 것 (원본에 이미 있음) | 쓰는 곳 |
|---|---|
| 도구별 오늘 토큰 (새로고침마다) | 경험치. 도구별 비율은 속성 성향 |
| 날짜 | 활동 일수, 하루 경험치 상한 |
| 현재 시각 | 시간대 성향(새벽 / 낮) |
| 5시간·주간 한도를 채운 기록 | 돌봄 실수 |
| 마지막 사용 뒤 지난 시간 | 잠 (표시만) |
| 버그 잡은 수 (화면에서 올라옴) | 배틀 승리 |

나가는 것은 상태(지금 디지몬, 단계, 경험치, 도감)와 사건이다. 사건의 예는 부화, 진화 후보가 생김, 진화함, 졸업이다. 화면은 사건을 받아 연출만 한다.

## 경험치 (토큰 낭비를 부르지 않게)

- **토큰 20만 개 = 경험치 1.** 경험치는 **하루 150까지만** 오른다. 토큰 3천만 개를 넘게 써도 더 오르지 않는다.
- 예를 들어 하루 2천만 토큰을 쓰면 하루 100이 오른다.
- 단계별 필요 경험치(제안)

| 단계 | 알 | 유년기 1 | 유년기 2 | 성장기 | 성숙기 | 완전체 | 궁극체 → 졸업 | 합계 |
|---|---|---|---|---|---|---|---|---|
| 경험치 | 20 | 40 | 60 | 120 | 200 | 280 | 300 | **1,020** |

- 한 줄을 끝까지 키우는 데 **활동일로 약 10일**이 걸린다. 지금 쓰는 빈도(주 2~3일)라면 3~5주다.
- 원본의 "성장 속도" 설정(10~200%)을 재사용해서 사용자가 조절할 수 있게 한다.
- 코딩을 안 하는 날은 경험치만 멈춘다. 죽거나 줄지 않는다(기준 원칙 3번).

## 진화 갈래 고르기

진화할 때가 되면 진화표(1단계 데이터)에서 다음 단계 후보를 뽑고, 아래 조건으로 점수를 매긴다.

| 조건 (그 단계에 머무는 동안 쌓인 기록) | 끌리는 쪽 |
|---|---|
| 낮 시간 위주로, 한도를 넘기지 않고 꾸준히 사용 | 백신 속성 |
| 여러 도구를 고르게 쓰거나 활동 일수가 많음 | 데이터 속성 |
| 새벽 비중이 **평소보다** 높거나, 한도를 채움(돌봄 실수) | 바이러스 속성 |
| 버그를 많이 잡음 | 전투형(공격 기술이 센 쪽) |

- **"평소보다"가 중요하다.** 새벽 비중을 고정 기준(예: 50%)으로 보지 않고, 사용자의 지난 평균과 비교한다. 원래 새벽에 일하는 비중이 큰 사람은 고정 기준이면 거의 항상 바이러스 쪽만 나오기 때문이다.
- **사용자가 고른다.** 점수 상위 후보 2~3개를 보여주고 사용자가 고른다. 하루 안에 안 고르면 1등으로 자동 진화한다(기준: 원하는 디지몬을 모으는 재미 우선).
- **숨겨진 진화는 몇 개만 둔다.** 조건을 만족해야 후보에 뜨는 특수 진화다. MVP에서는 각 카드에 1~2개만 둔다(예: 단데블몬 = 돌봄 실수가 많을 때, 블리츠그레이몬 = 버그를 많이 잡았을 때). 도감에 힌트를 보여준다.
- **오메가몬**은 워그레이몬과 메탈가루몬을 둘 다 졸업시켰을 때만 열리는 조그레스로 남겨둔다(MVP 이후).

## 코드 구조

새 폴더 `Sources/PokeTokenBar/Digimon/`에 모은다.

| 파일 | 하는 일 |
|---|---|
| `DigimonCatalog` | MVP 32종과 진화표를 읽는다. 1단계 데이터에서 MVP 카드만 뽑아 **Swift 코드 파일로 생성**한다. `Package.swift`에 리소스를 추가하지 않아 원본과 충돌이 적다. |
| `GrowthLedger` | 토큰 변화량을 경험치로 바꾸고(하루 상한), 시간대·도구·한도·활동일 기록을 쌓는다. |
| `EvolutionEngine` | 상태와 기록을 받아 후보, 진화, 졸업을 정한다. 난수와 시각은 밖에서 넣어서 테스트가 늘 같게 돈다. |
| `DigimonState` | 저장 형식(Codable): 지금 디지몬, 단계, 경험치, 지나온 길, 도감, 발견한 진화 경로, 졸업한 디지몬 |
| `DigimonStore` | 원본의 두 연결 지점(`updateCompanion`, `onStoreRefreshed`)에 붙는 어댑터. 원본 `CompanionStore`의 사용량 장부(설치 기준선, 도구별 오늘 사용량, 날짜 변경 처리)는 떼어 재사용한다. |

- 테스트는 `Tests/PokeTokenBarTests/Digimon*Tests.swift`에 둔다. 원본과 같은 XCTest를 쓴다.
- 대표 시나리오: 하루 상한, 날짜 넘어감, 갈래 점수, 사용자 선택과 자동 선택, 숨겨진 진화, 졸업 후 새 알, 저장과 불러오기
- 0단계에서 찾은 할 일도 같이 한다. 번들 ID, 저장 폴더, UserDefaults 이름을 PokeTokenBar와 다르게 바꾼다.

## 정할 것

2026-11-09에 세 가지 모두 제안대로 확정했다.

1. **경험치 속도:** 위 표(한 줄에 활동일 약 10일, 하루 상한 3천만 토큰)로 시작한다.
2. **갈래 고르기:** 후보 2~3개 중 사용자가 고르고, 하루 안에 안 고르면 자동으로 진화한다.
3. **새벽 기준:** 새벽 비중을 사용자의 평소와 비교한다.

- **숨겨진 진화 (MVP)**
  - 블리츠그레이몬·크레스가루몬: 그 단계에서 버그 20마리를 잡으면 열린다.
  - 단데블몬·니즈헤그몬: 그 단계에서 한도를 3번 채우면 열린다.
  - 열리면 후보 맨 앞에 온다.
- **잠긴 진화:** 오메가몬. 조그레스는 MVP 이후다.
- **점수(갈래 고르기)**
  - 백신 = 낮 비중 × (한도 안 넘김이면 1, 넘겼으면 0.5)
  - 데이터 = 쓴 도구 수(최대 3) × 0.5 + 활동일(3일이면 만점) × 0.5
  - 바이러스 = (이번 단계 새벽 비중 − 평소 새벽 비중) × 2 + 한도를 채운 횟수(최대 3) × 0.3
  - 애니 대표 진화 +0.15, 열린 숨겨진 진화 +2
- **확인한 것**
  - 데이터상 모든 완전체에 숨겨지지 않은 궁극체가 있다(워그레이몬, 메탈가루몬). 그래서 숨겨진 조건을 못 채워도 중간에 줄이 끊기지 않는다.
  - 이 저장소의 결함 대응 규칙에 따라, 안전장치 세 개를 일부러 망가뜨려 테스트가 실패하는지 확인했다. 대상은 잠금 규칙, 하루 상한, 평소 새벽 비중 비교다.
  - 오메가몬 잠금은 실제 데이터로는 도달할 수 없는 경로라, 그 경로를 만든 가짜 진화표로 시험한다.
- **아직 안 한 것 (3단계):**
  - 원본 `CompanionStore` 자리에 연결하기
  - 화면 붙이기
  - 번들 ID·저장 폴더 이름 바꾸기
  - 버그 잡은 수와 한도 채움을 엔진에 넘기기
  - 원본의 사용량 장부 재사용
