# 3단계: 화면 연결

정리일: 2026-11-10 · 상태: **구현함.** 앱을 빌드해 `/Applications/DigiTokenBar.app`에 설치하고 실제 사용 기록으로 켜 봤다.

## 한 일

| 조각 | 파일 | 내용 |
|---|---|---|
| 앱 이름 분리 | `Core/AppIdentity.swift`, `scripts/build-app.sh` | 앱 이름, 번들 ID, 저장 폴더, 로그, URL 스킴, 로그인 항목을 DigiTokenBar로 바꿨다. PokeTokenBar와 같이 깔아도 서로 건드리지 않는다. 업데이트 확인은 껐다. |

| 그림 받기 | `Digimon/DigimonSprites.swift` | 처음 필요할 때 Wikimon에서 받아 저장 폴더에 둔다. 30일이 지난 그림은 바뀌었는지만 물어본다. 앱 안에 디지몬 그림은 없다. 알은 코드로 그린 무늬 알이다. |

| 알림 | `Digimon/DigimonNotifier.swift` | 부화, 진화, 진화 후보가 생김, 졸업 때 알린다. 원본의 동반자 알림 설정을 따른다. |

원본 포켓몬 코드(`CompanionStore`, 상점·가방·도감 화면)는 지우지 않았다. 언어와 설정 화면 때문에 `CompanionStore`는 아직 만들지만, 더는 자라지 않는다. PokeAPI를 받지 않고, 부화하지 않고, 사탕도 없다.

## 연결 흐름

```
UsageStore 새로고침
  → AppDelegate.updateCompanion()  → DigimonStore.update(오늘 도구별 토큰)
  → AppDelegate.onStoreRefreshed() → DigimonStore.recordLimitWindows(한도 창)
DigimonStore.onActivity(사건, 먹은 토큰)
  → DigimonSceneHub.play  → 모든 펫 화면에 먹기·진화 연출
  → DigimonNotifier       → 시스템 알림
펫 화면에서 버그를 잡음 → DigimonStore.recordBugDefeated()
팝오버 선택 카드        → DigimonStore.choose()
```

## 확인한 것

- 테스트: 새로 21개(장부 6, 한도 3, 저장소 6, 그림 5, 권한 1). 2단계 엔진 18개와 함께 전체가 통과했다.
- 일부러 망가뜨려서 테스트가 잡는지 봤다.
  - 설치 전 사용량을 세게 바꾸면 → 2개가 실패했다.
  - 데이터 없는 새로고침을 받게 바꾸면 → 1개가 실패했다.
  - 저장소 값을 제자리에서 고치게 바꾸면 → 무한 새로고침 테스트가 실패했다.
- MVP 그림 56개의 주소가 Wikimon에서 모두 열린다.
- 실제 앱: 설치하기 전에 쓴 그날의 토큰을 시작점으로 잡고, 경험치로 세지 않았다(설치 전 사용량 규칙).
- 화면 밖에서 그려 확인했다. 아구몬의 "꼬마 불꽃!" 공격, 다크 모드, 선택 카드 3장(그레이몬·실리컨몬·아르고몬), 메뉴바 2프레임과 알.

## 이번에 배운 함정

- **관찰 대상 값을 제자리에서 고치면 무한 반복이 된다.** 메뉴바는 디지몬 저장소를 관찰하고, 새로고침 때마다 `update`를 부른다. `saved.ledger.observe(...)`처럼 값을 제자리에서 고치면, 바뀐 게 없어도 관찰자에게 알림이 간다. 그러면 둘이 서로를 계속 부른다. 그래서 복사본에서 계산하고, 달라졌을 때만 저장한다.
  - Swift 6.4에서는 같은 값을 `=`로 다시 넣으면 알림이 가지 않는다. 처음에 이 경로로 결함을 넣어 봤더니 테스트가 통과했다. 잘못된 확인이었다. 실제 위험한 경로(제자리 수정)로 다시 넣어서 테스트가 잡는 것을 확인했다.
- **앱 밖 마우스를 지켜보면 macOS가 "입력 모니터링" 권한을 묻는다.** 바탕화면 펫 창은 디지몬보다 넓다(디지몬이 그 안을 걸어 다님). 그래서 마우스가 디지몬 위에 왔는지 알아야 한다. 처음엔 앱 밖 마우스 이동을 지켜보는 전역 감시를 썼다. 그랬더니 앱을 켜자마자 권한 요청(`kTCCServiceListenEvent`)이 떴다. 원본 플로팅 펫은 창이 펫 크기와 같아서 이런 감시가 필요 없었다. 지금은 펫이 보일 때만 마우스 위치를 1초에 10번 읽는다. 이 방식은 권한이 필요 없다. 디지몬 코드에 전역 입력 감시가 들어오면 실패하는 테스트(`DigimonPermissionTests`)를 넣었다.
- **화면 밖 창에서는 애니메이션 프레임이 멈춘다.** 스크린샷용으로 화면 밖에서 그리면 펫이 안 보인다. 확인할 때는 JS에서 `pet.update`와 `pet.draw`를 직접 불렀다. 실제 팝오버와 바탕화면 창은 보이는 창이라 상관없다.

## 남은 일

- 기술 이름은 아구몬·파피몬 줄기 8종만 있다. 나머지는 "공격"으로 나온다.
- 컬러판이 없는 8종의 메뉴바 그림은 줄이면서 조금 뭉개진다.
- 설정 화면에 포켓몬 항목(대표 포켓몬, 뒷모습 등)이 남아 있다.
- 앱 아이콘과 일부 문구(PokeTokenBar, poketokenbar://)가 아직 원본 그대로다.
- 일본어 등 다른 언어는 영어로 나온다.
- 서명이 임시(ad-hoc)라서, 키체인 허용을 묻거나 Claude 한도를 못 읽을 수 있다. 이번 실행 로그에 `keychainInteractionNotAllowed`가 찍혔다. `scripts/create-signing-cert.sh`로 로컬 인증서를 만들면 줄어든다.
